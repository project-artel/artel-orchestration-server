## Goal
한 **TestSuite**가 담은 여러 TestScenario를, **시나리오 내부 케이스의 의미적 순서는 절대 건드리지 않고**, **시나리오끼리의 실행 순서**만 재배치해 **게임 리셋 횟수를 최소화**한다. Orche는 **정렬·최적화 메커니즘**을 소유하되, **호환성 판정(semantic) 입력은 외부(정규화 or LLM 오라클)가 공급**한다.

## ⚠️ 자연어 제약 — 재조정된 핵심 판단
Agent가 주는 TestCase의 **사전조건·기대효과는 자연어**다(구조화 술어 아님). 따라서:
- 리셋 필요 판정 = **"직전 시나리오 종료 상태가 다음 시나리오 사전조건을 충족하는가?"** 이 판정 자체는 여전히 게임-무관 문제지만, **입력이 NL이라 Orche가 스스로 기호 비교를 못 한다.**
- 세 갈래 중 하나가 있어야 성립:
  - **(a) 수집 시 정규화**: NL 사전조건/기대효과 → canonical 상태 어휘의 **구조화 술어**로 변환 저장(메타데이터 레지스트리 + LLM 정규화). → 이후 Orche 기호 알고리즘 성립.
  - **(b) LLM 호환성 오라클**: Orche는 순서 최적화만, "A결과 ⊨ B사전조건?" 판정은 **Agent에 위임**해 yes/no+비용 행렬 수신.
  - **(c) 런타임 반응형**: 사전 계획 없이 실행 중 GAME_STATE로 Agent가 "계속/리셋" 판단.
- **메커니즘=Orche, 의미판정=(a)/(b)**. Orche는 "gold"의 의미를 몰라도, (a)/(b)가 준 호환성 위에서 정렬만 한다.
- **초기화를 "어떻게" 하는지는 몰라도 됨**(주입 setter/재시작 계층 소관). "언제 필요한가"(=위 충족 판정)만 필요.

### 결정 방향 (2026-07-28): (a) 작성 시 정규화 채택
- **Agent가 TestCase 작성 시 NL과 함께 구조화 pre/post를 산출**(메타데이터 레지스트리 어휘로). Orche는 그 struct로 기호 최적화. (b) 오라클보다 **저렴·결정적·재사용·Orche 깨끗** → 우선.
- 책임: **Agent = NL→구조화 정규화**(작성 시, 레지스트리 어휘 한정), **Orche = 술어 위 정렬·리셋최소화 + 런타임 재확인**.
- 계약 확장: TestCase = `{category, title, precondition_nl, precondition_struct, expected_nl, expected_struct}`. NL=사람/캔버스, struct=알고리즘.
- 전제: 메타데이터 레지스트리(어휘) 존재. 없으면 **MVP=최적화 없음**. (b) 오라클은 정규화 불가 케이스의 폴백.

## Non-goals
- **경로 탐색(bridging)** — "A.end에서 몇 스텝 더 플레이해 B.start로 이동"은 게임 상태전이 모델 필요 → **후속**. 여기선 "직접 호환이면 잇기, 아니면 리셋"까지.
- 케이스 단위 재정렬(시나리오 의미 훼손) 금지.
- 시나리오 자체 작성(P1/dep).

## Context / Constraints
- 각 시나리오: **시작상태**=첫 케이스 precondition, **유효 종료상태**=케이스 postcondition을 순서대로 전파한 결과.
- 리셋 수단·비용: 재시작(clean, 높음) / 씬리로드(중, 씬-스코프만) / **setter 워프**(낮음, 레지스트리가 "설정 가능"이라 선언한 상태만).
- 관측성(GAME_STATE)=런타임 안전망.

## Approach (Checklist) — 단계적, MVP는 최적화 없음
- [ ] **Step 0 (MVP): 최적화 없이** — TestSuite 내 시나리오를 **사용자 지정 순서**로 실행, **사이마다 재시작**. 정확·단순·게임무관. **P2의 기본 폴백이자 첫 출시선.**
- [ ] **Step 1: 호환성 입력 확보** — (a) NL→구조화 정규화 파이프라인 **또는** (b) LLM 호환성 오라클 중 택. 이게 있어야 최적화가 시작됨.
- [ ] **Step 2: 상태 모델** — (a) 채택 시: 시나리오별 start/effective-end를 술어집합으로(postcondition 전파) + 술어 만족 판정기. (b) 채택 시: 시나리오쌍 호환성 행렬을 오라클로 채움.
- [ ] **Step 3: 순서화(그리디)** — 시나리오 노드 간 "호환=리셋0 / 비호환=리셋비용" 간선으로 **총 리셋비용 최소 순열**(그리디→휴리스틱). setter 가능 상태(레지스트리 선언)는 저렴 리셋으로.
- [ ] **Step 4: 런타임 재확인(강건성)** — 계획은 낙관적으로, 실행 중 시나리오 종료 후 **실제 GAME_STATE observables로 다음 precondition 성립 검증** → 불성립 시 리셋 삽입. NL/오라클 오판도 방어.

## Validation
- **Commands:** `./mvnw test -Dtest=ResetMinimizationPlannerTest`
- **Expected:** 합성 술어 세트로 (a) 호환 시나리오 체이닝 시 리셋 0, (b) 비호환 시 리셋 삽입, (c) setter 가능 상태는 저렴 경로 선택, (d) 술어 없을 때 전부 재시작 폴백, (e) 런타임 관측값이 예측과 다르면 리셋 삽입.

## Risks & Rollback
- **Risks:** postcondition 불완전 → 오체이닝(→ Step3 런타임 재확인으로 방어). 순서화 복잡도(시나리오 多 시 조합 폭발 → 휴리스틱).
- **Rollback:** 플래너를 끄고 "시나리오 순서=사용자 지정, 사이마다 재시작"으로 폴백(P2 없이도 Run 동작).
