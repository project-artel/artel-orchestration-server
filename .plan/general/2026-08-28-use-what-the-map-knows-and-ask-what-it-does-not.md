# 2026-08-28 — 지도가 아는 것은 쓰고, 모르는 것은 반드시 묻는다

- Date: 2026-08-28
- Jira: None
- Status: Draft

## Goal

저작이 **지도가 아는 것을 빠짐없이 쓰고, 지도가 모르는 것은 하나도 빠짐없이 묻는다.**

두 문장이 전부다. 오늘 하루 실측으로 드러난 결함은 예외 없이 이 둘 중 하나를 어긴 것이었고,
"정보가 없어서" 생긴 것은 하나도 없었다.

## Non-goals

- **길 찾기를 우리가 대신하지 않는다.** 어디로 어떻게 가는지는 QA 실행 에이전트와 지도의
  몫이다. 저작은 "누구를 검증하나 + 대략의 순서"를 담은 To-Do 리스트를 낸다.
- **게임에 맞춘 규칙을 넣지 않는다.** 방향·초기화·진행도를 코드가 정하지 않는다. 지도가 말한
  것만 읽는다. 오늘 만들었다가 버린 `OneWayValues` · `ScenarioResetOrder` 가 그 선을 넘었다.
- **부분 저장을 하지 않는다.** 검수가 전량을 보므로 절반만 저장하면 "안 담겼다"가 거짓으로 뜬다.
- 시나리오 순서 최적화(초기화 최소화)는 **선택 사항**이다. 실행이 감당할 수 있으면 손대지 않는다.

## Context / Constraints

### 오늘 고친 것 — 전부 "지도는 알았는데 안 썼다"

| 결함 | 지도는 알고 있었나 |
|---|---|
| 전제를 산문으로 렌더한 뒤 정규식으로 되읽음 | `condition_tree` 1981행에 구조가 있었다 |
| 화면 사이 길을 저작에 안 보냄 | `scene_edge` 19간선에 조작까지 있었다 |
| `state_before`/`state_after` 를 pydantic 이 버림 | 오케가 계속 보내고 있었다 |
| 씬 간선을 `firstOrNull()` 로 집음 | 실행 가능한 `Return` 간선이 둘째였다 |
| `explain_case` 를 케이스마다 호출(42회) | 케이스 목록에 조작이 이미 적혀 있었다 |
| `made_by` 를 변수 단위로 판정 | `detail` 이 `0`/`+1` 을 구분하고 있었다 |
| 나눔과 검수가 서로 다른 규칙 | 같은 지도 사실을 두 곳이 다르게 읽었다 |

### 지금은 채워져 있는 칸(실측, 지도 26)

```
condition_tree     404 / 404      calls           404 / 404
watchable          413 / 413      loops_back_to    16 (되풀이 케이스 8건으로 이어짐)
scene_object_ref   197            scene_edge       19
```

### 비어 있지만 **의도된** 칸 — 버그가 아니다

- `hint_action_method` — QA 런이 성공한 조작을 캐시하는 자리. 아직 런이 없어서 비었다.
- `resolution` — 적재기가 일부러 기본값으로 둔다(해당 주석에 근거가 있다).
- `capability.repeat_until_done` — 생성기는 `capability_evidence.loops_back_to` 를 읽는다.
  이 칸에 쓰지 않는 것은 `ck_capability_repeat_needs_interaction` 이 코루틴을 막기 때문이고,
  그래서 사실을 근거 쪽으로 옮겼다(V54).

### 제약

- 사용자에게 보이는 TC 는 **사전조건 · 기능 · 기대결과** 셋 뿐이다. 저장 구조는 자유.
- 배포된 프롬프트 버전은 본문을 고칠 수 없다(`prompts-lock.json`). 새 버전을 만든다.
- 사용자가 시킨 것이 기본 규칙보다 **우선**이다.

## Risks & Rollback

- **Risks:**
  - 순서를 보장하는 코드가 없다. 오름차순으로 서는 것은 모델이 `needs:` 숫자를 읽은 결과이고,
    `position` 과 `StagePosition` 을 함께 거는 블록은 아직 역행한다. 이것을 코드로 정하려면
    "진행 축" 선언이 필요하고, 그건 지도에 없는 정보다 — 지어내면 게임마다 깨진다.
  - 한 게임(word-venture)에서만 검증했다.
  - 저작 품질이 판마다 흔들린다(시나리오 6~15개). 프롬프트로 좁혔지만 없애지는 못했다.
- **Rollback steps:**
  - `test_case.condition` 이 비면 `CaseConditionReader` 가 문장으로 물러선다 — 구버전 행과
    함께 도는 경로가 그대로 살아 있다.
  - 프롬프트는 `SCENARIO_PROMPT_VERSION` 으로 옛 버전을 지목하면 즉시 되돌아간다.
  - `questions` 는 더한 칸이라 옛 화면은 `question` 하나만 계속 읽는다.

## Open Questions

- **QA 실행이 "저절로 일어나는" 전제를 스스로 만들 수 있나.** `stagePosition == 1` 은 전투를
  이겨야 오른다. 저작은 그 자리를 정확히 짚어 주지만 만들지는 못한다. 실행 쪽이 감당하면
  ②는 닫히고, 못 하면 "진행 축" 계약을 만들어야 한다.
- **진행 축을 누가 선언하나.** 사람이 게임당 한 번인지, QA 실행이 관측해 쌓는지.
  뒤엣것이 강하지만(추론이 아니라 본 것) 첫 판은 아는 것이 없다.
- **한 화면에 케이스가 하나뿐인 씬**(GameOverScene)은 여정에 못 붙으면 1스텝 카드가 된다.
  그대로 두는 것이 맞는지, 인접 여정에 억지로 붙이는 것이 맞는지.
