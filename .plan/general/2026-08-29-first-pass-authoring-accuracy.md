## 오늘의 결론 — 첫 판이 왜 틀리나

**모델이 아니라 `findPath` 가 틀린 답을 낸다.** 런 212 실측:

```
1636 → 1637   KNOWN [7440]      ← 오케가 "RightArrow 로 이어진다"고 답함
```

그런데 `1636`(`StagePosition >= 1`) → `1637`(`>= 2`) 는 **전투가 필요한 자리**다.
`7440` 은 지도의 `RightArrow` 라 진행도를 안 올린다.

사슬이 이렇다:

```
findPath        틀린 답                       ← 첫 번째 잘못
모델            시킨 대로 CAPABILITY 7440 적음  ← 프롬프트 지시대로. 정직함
bridge()        모델 문장 위에 그 답을 도장 찍음 ← 두 번째 잘못
검수            7440 은 실재 → 통과
```

`bridge()` 의 덮어쓰기 규칙("둘이 다르면 명세가 맞다")은 **명세가 맞을 때만** 옳다.
이번엔 거꾸로 작동해 맞는 쪽을 버렸다.

**원인**: 저절로 오르는 값을 메울 자리로 세는 코드가 아침 되돌림에 함께 빠졌다.
